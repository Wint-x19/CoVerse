# 创建 Issue

## 前置

- 需求模糊时不猜测,先用具体问题向用户澄清范围,确认后再建 Issue。
- Issue 是单个开发任务的产品 PRD 默认载体。创建前必须确认目标用户与使用场景、产品目标、产品需求、非目标、边界与异常场景及验收标准;不允许用 `TBD`、空章节或笼统描述占位。
- PRD 有未确认事项时停留在需求澄清阶段,不要执行后续 Issue 创建动作。只有全部内容确认后,才能在最终 Issue 中将「待确认事项」写为“无”、将「PRD 状态」写为 `Ready`;后续需求变化时先更新 Issue,重新确认后再继续开发。
- 重构、依赖升级、CI 或文档等非产品型任务也要写 PRD,其中目标用户可以是开发者或维护者,使用场景可以是开发、发布或运维流程;内容可以简洁,但不能编造、留空或用占位符代替。
- **先查重,再新建**:确认范围后,先搜索仓库现有 Issue / PR,确认这件事没有被解决过、也没有人正在做:
  - `gh issue list --search "关键词" --state all` 和 `gh pr list --search "关键词" --state all`,关键词换几组说法(中英文、同义词、模块名)多搜几遍。
  - **已被解决**(Issue 因修复而关闭、或相关 PR 已合并)→ 把编号和链接报给用户,不新建。注意 closed 不等于已解决:wontfix / duplicate 关闭的 Issue、未合并就关掉的 PR 都不算。
  - **进行中的**(open 的 Issue 或 PR)→ 把编号、状态、和本需求的重合程度报给用户,由用户决定是跟进已有的还是仍要新建;新建时在正文里引用相关编号说明区别。
  - 例外:交 PR 阶段补建 Issue 时只查 Issue、不查 PR(此时的 PR 就是自己正要提交的)。
- 大任务先拆成可独立验证的小步骤,一个 Issue 对应一件事。

## 写作风格

- 中文为主,代码路径 / 术语保留英文。
- 从第一性原理出发,用最直白、不绕弯的话在 PRD 中回答三问:
  1. **要解决什么问题?**(现状哪里不对,谁受影响)
  2. **为什么值得解决?**(不解决的代价)
  3. **做完后怎么算解决了?**(可验证的验收标准)
- 不写实现细节。审阅者是人,实现方案留给 PR 阶段。

## 标题

`【模块】动词开头的一句话`,例如 `【适配器】修复 Codex 桌面上下文缺少调用 ID 时导入失败`。

模块标签用 `AGENTS.md`「模块划分与【】标签」小节的标签;标题只标最主要的 1 个,其余模块写在正文「涉及模块」。GitHub label 使用同表 `GitHub label` 列的英文名,不要把中文【模块】标签直接传给 `--label`。

## 正文模板

```markdown
## 背景

<!-- 问题是什么、谁受影响,2-4 句直白描述 -->

## 产品 PRD

### 目标用户与使用场景

<!-- 谁在什么场景下使用或受到影响 -->

### 产品目标

1. <!-- 编号列表,每条可独立验证 -->

### 产品需求

1. <!-- 描述用户可感知的行为,不写具体实现 -->

### 非目标

- <!-- 明确本次不解决什么,避免范围蔓延 -->

### 边界与异常场景

- <!-- 权限、失败、空状态、兼容性、转换损耗等场景 -->

### 验收标准

- [ ] AC-1: <!-- 每条使用稳定编号并描述可验证结果,供 PR 自测案例引用 -->

### 待确认事项

<!-- 全部确认后填写“无”;仍有未确认事项时不要创建 Issue -->

### PRD 状态

<!-- 所有 PRD 必填内容确认后填写 Ready;否则不要创建 Issue -->

## 涉及模块

【xx】<!-- 引用 AGENTS.md 模块标签 -->
```

## 动作

1. 用 `gh issue create --title "..." --body "..." --label "<module>"` 直接创建;涉及多个模块时重复传 `--label`,例如 `--label "core" --label "adapters"`。**草稿不落盘进仓库**——不要生成 `ISSUE_DRAFT` 之类的文件。
2. 创建后把 Issue 编号和链接报给用户。
3. 再次确认 Issue 的「待确认事项」为“无”且「PRD 状态」为 `Ready`;不满足时停下并继续澄清,不得切开发分支。
4. 如果接下来要开发,从 `main` 切分支,命名 `type/issue-id-短描述`(如 `bugfix/12-codex-browser-tabs`)。
