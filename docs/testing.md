# Agent 测试流程

每次修改先写清楚用户能观察到的结果，再选择能验证该结果的测试。例如，修复“导入成功后侧栏没有刷新”时，验收条件是用户无需重启即可在侧栏打开新会话，并能读到样本中的消息。

## 从改动选择测试

| 改动范围 | 优先验证 | 桌面验收条件 |
| --- | --- | --- |
| 文档、说明 | 核对相对链接、命令和涉及的配置项 | 跳过 Computer Use |
| 协议、适配器、核心、CLI | 用经审核的样本运行相关 Vitest 用例，核对输出、错误及转换损耗 | 仅当改动还影响用户可见的桌面行为时，按下行处理 |
| 桌面服务、IPC、渲染界面 | 运行相关服务和 IPC 用例；有组件或窗口自动化用例时，运行覆盖此次改动的用例 | 自动化通过后，若用户操作或可见结果仍待确认，用 Computer Use 走一遍受影响路径 |
| 原生交互、窗口布局、打包 | 运行相关自动化，构建与问题相符的桌面产物 | 在目标系统验证受影响的行为，如文件拖入、键盘焦点、指定显示缩放或安装后的首次启动 |

1. **先做定向回归。** 新功能随附测试。修复缺陷时，优先用能稳定复现问题的最小用例验证修复前后的差异。新检出仓库或修改包代码后先运行 `pnpm build`，使测试加载本次构建的包。桌面服务和 IPC 的定向命令为 `pnpm exec vitest run packages/ui/test/desktop.test.ts`。
2. **再按影响面扩大检查。** 涉及共享接口或跨包流程时运行 `pnpm check`，覆盖构建、类型检查、Vitest、样本校验、冒烟和离线回归。该命令验证的范围止于离线检查，真实窗口中的点击、布局和系统对话框需要单独验证。
3. **处理失败后再验收。** 常规用例失败时，先依据失败断言和日志修复，再重跑相关用例。只有当故障本身必须在真实窗口复现时，才提前使用 Computer Use 定位；修复后仍按上述顺序回归。

## 何时使用 Computer Use

Computer Use 指 Agent 通过可见窗口、鼠标和键盘操作真实客户端。默认先运行可重复的自动化测试。如果现有窗口自动化已经覆盖同一操作和可见结果，可以跳过重复点验。需要使用 Computer Use 时，按下面的步骤执行。

1. **确定验收路径。** 写下入口、操作和可见的通过条件。日常验收只走一遍本次受影响的路径；故障复现保留触发条件，例如窗口宽度、系统缩放或拖入的文件类型。
2. **准备样本和客户端。** 使用经审核的 fixture 或合成会话，将 `COVERSE_DATA_DIR` 指向仓库 `.tmp/` 下本次验收专用的目录；涉及目标 Agent 写入时，另选测试用项目和测试会话。构建后用 `pnpm ui` 启动真实 Electron 窗口。核验打包问题时用 `pnpm ui:pack` 生成并启动打包产物；核验安装问题时用 `pnpm ui:dist` 生成安装包，从安装后的应用入口测试。
3. **从用户入口操作并核对结果。** 例如验收导入刷新时，从导入界面选择样本，完成导入后立即从侧栏打开记录，核对消息正文及顺序。验收拖拽时从系统文件管理器拖入。验收重启恢复时完全退出应用，用同一个测试数据目录重开。
4. **记录结果。** 在交付说明中列出实际运行的命令及结果。使用过 Computer Use 时，注明平台、开发版或打包版、操作路径和观察结果。失败时记下预期、实测和复现条件，按需保留脱敏截图或日志，并将能自动判定的问题补成回归用例。环境限制导致必要的窗口验收未执行时，标明待验证项。
